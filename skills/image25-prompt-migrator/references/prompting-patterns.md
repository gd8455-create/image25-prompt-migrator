# GPT Image 2.5 轉換模式

只在 `migration_convert` 或合格的 `migration_repair` 需要重組既有提示詞時讀取。以下結構是語意整理工具，不是固定模板；每一項都必須能追溯到 `source_prompt`、實際參考資產或使用者對來源的明確說明。

複雜 JSON、視覺錨點、角度／毫米描述或長負面清單，依[結構化場景稽核](structured-scenes.md)處理。篇幅、JSON 格式與數值密度不作為升級或有效性的證據。

## 建立語意保留表

先從來源辨認：

- 成品類型與用途，如果來源有寫。
- 主體、身份、數量、動作、視線與互動。
- 場景、時間、構圖、位置、比例與取景。
- 顏色、材質、光線、媒介與明確風格。
- 每個必須成像的逐字字串與排版要求。
- 需要保留或排除的內容。
- 每張實際參考圖的用途與優先關係。

來源沒寫的欄位保持缺省。不要為了讓格式完整而新增鏡頭、天氣、人物特徵、品牌、場景物件或畫質詞。

## 組織 `converted_prompt`

依來源實際包含的內容，使用自然、直接的 GPT Image 2.5 指令。複雜提示詞通常可按以下順序整理，但順序可隨語意調整：

1. 成品與任務。
2. 主體與可見動作。
3. 場景與構圖。
4. 材質、光線、色彩和其他可見細節。
5. 必須成像的文字。
6. 與成功條件直接相關的限制。

合併同義堆疊時保留原本強調程度。抽象畫質詞只有在沒有獨立創作意義時才可刪減。相機或鏡頭詞視為外觀線索，不能承諾精確光學模擬。

## 來源本身是圖片編輯指令

若 `source_prompt` 已經要求編輯一張或多張圖片，保留其編輯語意並整理成：輸入角色、本次修改、必須保留、與修改相關的整合條件、不得新增。這只是把既有編輯提示詞遷移至 GPT Image 2.5；沒有來源提示詞時不能使用這個結構發明編輯任務。

每張實際圖片都要編號並指派角色，例如身份、服裝、產品、構圖、背景、材質、色調或風格。說明如何組合，以及衝突時哪張優先。沒有圖片時不得假裝已檢視圖片或建立虛構路徑。

要求指定區域以外像素完全相同時，提示詞不能保證結果；在限制中標示可能需要遮罩、合成或其他確定性後製。

## 精確文字

每個必要字串使用引號，保留大小寫、標點、出現次數、位置、字體、顏色和相對大小。必要時逐字母登記罕見名稱。

「不要其他文字」「不要 Logo」「不要浮水印」只能排除登記以外的內容。來源要求姓名、署名、產品標籤或場景文字時，不能保留與之衝突的廣泛禁止句。生成後仍需逐字校對。

## 控制與提示詞分流

先依 [來源轉接原則](source-adapters.md) 辨認來源控制。只有畫面語意進入 `converted_prompt`。模型、品質、實際像素尺寸、背景和輸出格式等已知控制進入 `request_settings`，且只使用目標操作面確實提供的值。

來源參數即使名稱相似，也不能自動視為 GPT Image 2.5 的同一控制。沒有直接等價或操作面未暴露時，記錄限制，不把參數名稱和值寫成提示詞咒語。

## 失敗後的最小修復

在 `migration_repair` 中，把觀察到的失敗逐項連到語意保留表。例如必要文字錯誤，就加強逐字內容、次數與位置；身份或產品漂移，就澄清實際參考圖角色與優先關係。只修改有證據支持的歧義或遺漏，並保持每一項修改可追溯到來源要求。
